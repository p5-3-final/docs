# ADR-0004 브라우저에서 접근 토큰은 메모리에, 재발급 토큰은 HttpOnly 쿠키에 둔다

## 맥락

SPEC-001은 로그인 응답으로 15분짜리 접근 토큰을 본문에, 14일짜리 재발급 토큰을 `HttpOnly`·`Secure`·`SameSite=Strict` 쿠키(`Path=/api/v1/auth`)로 준다. frontend(SPEC-002)는 접근 토큰을 어디에 두고, 새로고침이나 새 탭에서 로그인 상태를 어떻게 되살릴지 정해야 한다. frontend `AGENTS.md`는 이 방식을 ADR로 정할 때까지 `localStorage` 사용을 막아 두었다.

## 결정 요인

- 토큰 탈취 피해를 줄여야 한다. 앱에 XSS가 생겨도 오래 쓸 수 있는 토큰이 유출되면 안 된다(원칙 VII).
- 이미 머지된 SPEC-001 계약(본문 접근 토큰, 쿠키 재발급 토큰)을 바꾸지 않는다.
- 6명 팀, 프로젝트 기간 안에 만들 수 있어야 한다. 서버를 하나 더 두는 구성은 피한다.
- 새로고침, 새 탭에서 다시 로그인하지 않아야 한다(SPEC-002 R-8).

## 검토한 선택지

### 1. 접근 토큰은 메모리, 재발급 토큰은 HttpOnly 쿠키

- 장점: 스크립트가 읽을 수 있는 저장소에 토큰이 남지 않는다. XSS가 생겨도 재발급 토큰은 읽을 수 없고, 접근 토큰은 15분 뒤 만료된다. SPEC-001 계약을 그대로 쓴다.
- 단점: 새로고침이나 새 탭을 열 때마다 재발급 요청이 한 번 필요하다. 재발급 토큰이 회전하므로 동시에 두 번 재발급하면 재사용으로 감지되어 로그인 계열 전체가 폐기된다. 그래서 frontend가 재발급 요청을 한 번에 하나만 보내야 한다.

### 2. 접근 토큰을 localStorage에 저장

- 장점: 새로고침해도 재발급 없이 바로 쓴다. 구현이 가장 단순하다.
- 단점: XSS가 생기면 스크립트가 토큰을 그대로 읽어 간다. 탭 사이에 같은 토큰이 공유되어 만료·로그아웃 처리가 복잡해진다.

### 3. 접근 토큰도 HttpOnly 쿠키로 받기

- 장점: 스크립트가 어떤 토큰도 읽지 못한다.
- 단점: SPEC-001 계약(본문 접근 토큰, 게이트웨이의 `Authorization` 헤더 검증)을 바꿔야 한다. 쿠키로 인증하므로 CSRF 대비가 따로 필요하다.

### 4. BFF(Backend for Frontend)가 세션으로 토큰을 보관

- 장점: 브라우저에는 세션 쿠키만 있고 토큰은 서버에만 있다.
- 단점: 배포 단위와 세션 저장소가 하나씩 늘어난다(ADR-0003 범위 밖). 팀 규모와 기간에 비해 크다.

## 결정

**1. 접근 토큰은 메모리, 재발급 토큰은 HttpOnly 쿠키**를 택한다. 이유: SPEC-001 계약을 바꾸지 않고, 스크립트가 읽을 수 있는 저장소에 토큰을 남기지 않으며, 추가 서버 없이 만들 수 있다.

- 접근 토큰은 JavaScript 메모리에만 둔다. `localStorage`, `sessionStorage`, IndexedDB, 스크립트가 읽을 수 있는 쿠키에 저장하지 않는다.
- 앱이 시작될 때(새로고침, 새 탭) 재발급 API를 호출해 접근 토큰을 받는다. 재발급 토큰이 없거나 거절되면 로그아웃 상태로 시작한다.
- 재발급 요청은 앱 안에서 한 번에 하나만 보낸다. 동시에 필요하면 진행 중인 요청의 결과를 같이 쓴다.
- 이 방식은 2026-11-02 사용자가 선택했다.

## 결과

- 좋아지는 점: XSS가 생겨도 오래 쓸 수 있는 토큰이 노출되지 않는다. 계약과 backend 변경이 없다.
- 감수할 점
  - 페이지를 열 때마다 재발급 요청이 하나 생긴다.
  - 여러 탭이 거의 동시에 열리면 탭끼리 재발급이 겹쳐 재사용으로 감지될 수 있다. 이 경우 다시 로그인해야 한다. 자주 생기면 탭 간 조율(BroadcastChannel 등)을 후속으로 검토한다.
  - Safari는 `http://localhost`에서 `Secure` 쿠키를 저장하지 않을 수 있다. 로컬 개발은 Chrome 계열 브라우저 기준으로 확인한다.
- 후속 작업
  - frontend `AGENTS.md`의 "ADR로 결정할 때까지" 문구를 이 ADR 링크로 바꾼다.
  - SPEC-002 plan에서 재발급 단일 요청(single-flight)과 만료 시 재시도를 설계한다.
