# ADR-0011 영상 삭제 시 비식별 파생 데이터는 동의를 받아 1년 동안 학습용으로 보존한다

## 맥락

지금은 영상을 지우면(`video.deleted`) 모든 서비스가 그 영상의 파생 데이터까지 지운다([SPEC-003](../specs/SPEC-003-video-upload/spec.md) R-21, [SPEC-009](../specs/SPEC-009-ai-gateway-analyze/spec.md) R-20). 그래서 예측 모델을 학습할 데이터가 쌓이지 않는다([ADR-0010](0010-v4-evaluation-readiness.md) "맥락").

예측의 정답(예: "방호 제거 후 10분 안에 사람이 들어왔는가")은 확정 이벤트와 위험 상태 기록에서 자동으로 계산된다. 이 기록에는 사람을 알아볼 수 있는 정보가 없다. 개인정보는 영상·프레임·크롭에 있고, 이벤트 시각과 구역 이름에는 없다.

## 결정 요인

- 개인정보 원칙: 블러 사본만 저장·전송하고, 사용자가 지운 영상을 다시 볼 수 있는 경로를 남기지 않는다.
- 보존은 사용자가 명시적으로 동의한 범위에서만 한다. 동의를 철회할 수 있어야 한다.
- 운영 비밀값은 AWS Secrets Manager가 원칙이지만, 이 프로젝트 환경에서 쓰지 못할 수도 있다.
- 파생 데이터는 여러 서비스(analysis, search, quality 등)에 나뉘어 있다. 같은 영상에서 나온 보존 데이터는 서비스가 달라도 같은 키로 묶여야 학습 데이터로 쓸 수 있다.

## 검토한 선택지

### 1. 지금처럼 모두 삭제

- 장점: 개인정보 위험이 가장 작다. 바꿀 것이 없다.
- 단점: 예측 학습 데이터가 쌓이지 않는다.

### 2. 파생 데이터를 모두 보존

- 장점: 데이터가 가장 많이 남는다.
- 단점: 크롭·프레임·모델 원문에 사람이 남는다. 지운 영상을 다시 볼 수 있게 된다.

### 3. 등급을 나누고, 동의한 영상의 비식별 파생 데이터만 보존

- 장점: 개인정보가 있는 데이터는 지금처럼 바로 지우면서, 학습에 필요한 기록만 남는다.
- 단점: 삭제 처리가 등급별로 갈린다. 동의·철회·기간 만료를 관리해야 한다.

### 보존 키 방식

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| 단순 해시 SHA-256(sourceId) | 키 관리가 없다. | sourceId를 아는 사람은 계산해서 원래 영상과 다시 이을 수 있다. |
| 서비스마다 무작위 ID | 다시 잇기가 가장 어렵다. | 같은 영상의 보존 데이터를 서비스 사이에서 묶을 수 없고, 철회 시 지울 대상을 찾을 수 없다. |
| 비밀 키 해시 HMAC-SHA256(키, sourceId) | 키 없이는 다시 이을 수 없다. 같은 영상은 서비스가 달라도 같은 값이다. 철회 때 다시 계산할 수 있다. | 비밀 키를 관리해야 한다. |

## 결정

**선택지 3**과 **비밀 키 해시**를 택한다. 이유: 개인정보가 있는 데이터의 삭제 원칙은 그대로 두고, 사용자가 동의한 영상에서만 사람을 알아볼 수 없는 기록을 남겨 예측 학습 데이터를 쌓는다.

### 등급

| 등급 | 대상 | 영상 삭제 시 |
| --- | --- | --- |
| (a) 즉시 삭제 | 원본·정규화 사본·HLS, 구간 대표 프레임, 트랙 크롭, 검출 박스 파일, 근거 프레임, 주석 클립, 벡터, 모델 원문, 검색 질의·결과 | 동의와 상관없이 지금처럼 바로 지운다. |
| (b) 학습용 보존 | 이벤트 유형·시각·구역·severity·판정 상태, 위험 상태와 노출 지표, 궤적 요약(좌표 통계), 정적 객체 재고 변화 | 동의한 영상이면 sourceId를 보존 키로 바꿔 남기고, 아니면 지운다. |

- (b)에는 이미지·벡터·자유 문장(설명문, 위험 사유, 조치 제안)·사용자 ID를 넣지 않는다. 자유 문장은 화면 속 글자나 사람 묘사가 들어갈 수 있어 (a)로 둔다.
- 영상이 남아 있는 동안에는 등급과 상관없이 지금처럼 쓴다. 등급은 삭제할 때만 적용한다.
- (b) 데이터는 오프라인 학습 데이터 내보내기(ADR-0010 ⑨ 특징 내보내기)에만 쓴다. 처리 경로에서 모델을 학습하거나 고치지 않는다. 학습은 레포 밖 학습 작업에서 하고, 학습한 모델은 모델 산출물 규약(ADR-0010 ②)과 Shadow·Canary를 거쳐 반영한다.
- 어떤 데이터가 (a)·(b)인지는 각 서비스가 자기 데이터에 대해 spec에서 정한다. 이 표에 없는 데이터는 (a)다.

### 동의

- 동의는 영상마다 고를 수 있고, 계정 기본값도 둘 수 있다. 새 영상은 계정 기본값을 따르고, 영상마다 바꿀 수 있다.
- 기본값은 "보존하지 않음"이다. 사용자가 고르지 않으면 지금처럼 모두 지운다.
- 동의와 계정 기본값은 media-service가 저장한다. 보존 동의는 영상 데이터에 대한 설정이라 auth-service는 바꾸지 않는다.

### 보존 키

- 보존 키는 HMAC-SHA256(비밀 키, sourceId)다. media-service만 비밀 키를 갖고, `video.deleted`에 등급과 보존 키를 실어 보낸다. 다른 서비스는 받은 보존 키를 그대로 쓰고 키를 계산하지 않는다.
- 비밀 키는 운영에서 Kubernetes Secret으로 주입한다. AWS Secrets Manager를 쓸 수 있게 되면 External Secrets 등으로 같은 Secret을 채운다. 로컬은 환경변수다.

### 기간과 철회

- (b) 데이터는 영상을 지운 시각부터 1년 동안 둔다. 각 서비스가 1년이 지난 보존 데이터를 지운다.
- media-service는 지운 영상의 최소 기록(sourceId, 소유자, 동의 여부, 삭제 시각)을 같은 기간 동안 남긴다. 철회할 때 보존 키를 다시 계산하는 데만 쓴다.
- 사용자가 동의를 철회하면 media-service가 보존 키를 실은 철회 이벤트를 발행하고, 각 서비스는 그 키의 보존 데이터를 지운다. 영상이 아직 남아 있으면 동의만 끄고 이벤트는 내지 않는다.
- 외부 데이터셋에서 가져온 영상(ADR-0010 ⑨)은 이 규칙이 아니라 Golden Set 관리 규칙을 따른다.

## 결과

- 좋아지는 점:
  - 동의한 영상에서 예측 학습 데이터(이벤트·위험 상태·노출)가 쌓인다.
  - 개인정보가 있는 데이터의 삭제는 지금과 같다.
  - 비밀 키가 media-service 한 곳에만 있다.
- 감수할 점:
  - DB를 가진 모든 서비스의 `video.deleted` 처리가 등급에 따라 갈리고, 철회 이벤트와 1년 만료 정리 작업이 늘어난다.
  - media-service가 지운 영상의 최소 기록을 1년 동안 남긴다.
  - 비밀 키를 잃으면 철회 때 보존 키를 다시 계산할 수 없다. 키 교체는 별도 절차가 필요하다.
  - 운영 비밀값을 Secrets Manager가 아니라 Kubernetes Secret으로 둘 수 있다(루트 `AGENTS.md` 보안 규칙의 예외). Secret은 gitops에 평문으로 커밋하지 않는다.
- 후속 작업: [아키텍처 v4 전환 작업 목록](../architecture/legacy/v4-transition.md) D-7, F-2
  - 계약: `video.deleted`에 등급과 보존 키, 동의 철회 이벤트, Media API의 영상별 동의·계정 기본값
  - media-service: 동의 저장, 삭제 기록, 철회 이벤트, 보존 키 계산
  - 각 서비스: 자기 데이터의 등급 표시와 삭제·만료·철회 처리. 다른 담당자 서비스는 계약만 정하고 구현은 각 담당이 한다.
