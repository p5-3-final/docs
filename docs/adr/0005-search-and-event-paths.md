# ADR-0005 분석을 검색 경로와 이벤트 경로로 나누고 17개 배포 단위를 다시 구성한다

## 맥락

[ADR-0003](0003-service-composition.md)은 분석할 때 정적이 아닌 모든 구간을 VLM으로 설명하는 구조(구간 설명 중심)를 전제로 17개 배포 단위를 정했다. 이 구조를 다시 검토한 결과는 다음과 같다.

- 분석 시점 AI 비용이 영상 1시간에 약 330~600원이다. 대부분은 아무도 검색하지 않을 구간의 설명에 쓰인다.
- 문장 검색은 VLM이 미리 써 둔 구간 설명 텍스트와만 비교하므로, 설명에 없는 외형(옷 색, 날씨 등)은 찾기 어렵다.
- 이벤트 후보가 규칙, 구간 VLM, 상호작용의 세 경로에서 나와, 후보를 모으고 기다리는 단계(`chunk.completed`, 기대 후보 수 합산)가 완료 판정을 복잡하게 만든다.
- 구간 설명과 이미지 기반 2단계 요약 때문에 개발 기간이 혼자 기준 9~11개월로 추정된다.

## 결정 요인

- 6명 팀, 최종 프로젝트 기간 안에 MVP(검색, 이벤트, 클릭 조회)를 시연해야 한다.
- 분석 시점 외부 AI 비용을 줄이고, 비용이 실제 사용량(검색 횟수)에 비례하게 한다.
- 문장으로 장면을 찾아 그 시각으로 이동하는 기능은 유지한다.
- 서비스마다 자기 DB를 소유하고 상태 변경은 Kafka 이벤트로만 전달한다(원칙 IV, [ADR-0002](0002-kafka-message-broker.md)).
- 모든 서비스가 여러 Pod로 실행돼도 결과가 같아야 한다.

## 검토한 선택지

### 1. 구간 설명 중심 유지 (ADR-0003)

- 장점: 행동·맥락 질의에 강하다. 검색 응답이 텍스트 비교만 해서 1초 안팎이다.
- 단점: 분석 시점 비용이 크다(1시간 약 330~600원). 외형 질의가 약하다. 후보 대기와 2단계 요약 때문에 완료 판정과 개발 범위가 크다.

### 2. 검색 경로 + 이벤트 경로 (VLM은 필요한 순간에만)

- 검색 경로: 키프레임을 SigLIP 2 이미지 인코더로 벡터화해 두고, 질의가 오면 벡터·텍스트 인덱스로 후보를 찾은 뒤 상위 장면만 VLM으로 재순위화한다.
- 이벤트 경로: YOLO·추적·자세 추정과 이벤트 정의 목록의 규칙이 후보를 내고, VLM은 후보만 판정한다. 결과는 타임라인과 텍스트 검색 인덱스에 저장한다.
- 장점: 분석 시점 비용이 1시간 약 50~90원으로 준다. 외형·장면 질의는 이미지 벡터로, 행동 질의는 이벤트 인덱스로 나눠 처리한다. 후보가 한 경로라 청크당 한 건으로 묶을 수 있어 대기 단계가 사라진다. 재순위화 모델은 재처리 없이 바뀐다. 개발 기간 추정이 6~8개월로 준다.
- 단점: 검색 응답이 2~5초로 추정된다(PoC 실측 필요). 이벤트 재현율이 YOLO와 규칙의 후보 재현율에 묶인다. 프레임 벡터와 질의 벡터의 인코더 버전이 어긋나면 검색이 조용히 망가진다.

### 3. 이벤트 경로만 (문장 검색은 이벤트 텍스트로만)

- 장점: 가장 단순하고 싸다. 이미지 인코더와 재순위화가 필요 없다.
- 단점: 이벤트 정의 목록에 없는 장면(외형, 장면 묘사)은 검색할 수 없어, 문장으로 장면을 찾는 핵심 기능이 약해진다.

## 결정

**선택지 2, 검색 경로 + 이벤트 경로**를 택한다. 이유: 핵심 기능(문장으로 장면 찾기)을 유지하면서 분석 시점 비용과 개발 범위를 크게 줄이고, 후보 대기를 없애 완료 판정을 단순하게 만든다.

배포 단위는 17개를 유지하고 역할을 다음과 같이 바꾼다.

| 구분 | 변경 |
| --- | --- |
| vlm-worker | 제거. 자리를 **frame-encoder**(키프레임 → SigLIP 2 이미지 벡터)가 대신한다. |
| chunk-processor | 구간 샘플링 대신 1fps 키프레임 추출·중복 제거·블러와 이벤트 후보(청크당 1건)를 함께 만든다. |
| event-analyzer | 후보 대기와 병합 단계를 없애고, 청크 후보 묶음을 받아 바로 판정한다. |
| track-analyzer | 모든 트랙이 아니라 이벤트 관련 트랙과 사용자가 클릭한 트랙만 분석한다. |
| aggregator | 청크 요약을 없애고, 청크 경계 이벤트 병합, 시간 기준 규칙(배회), 이벤트 설명문 기반 텍스트 요약을 맡는다. |
| embedding-worker | 구간 설명 대신 이벤트 설명문, 트랙 속성, 프레임 주석을 임베딩한다. |
| search-service | 프레임 벡터 적재, 질의 해석·재순위화 지휘(ai-gateway 동기 호출), 결과 재사용, 프레임 주석을 맡는다. |
| ai-gateway | 질의용 SigLIP 2 텍스트 인코더를 함께 돌린다. |

Python 워커의 이미지는 [ADR-0001](0001-ai-uv-workspace.md)대로 워커마다 따로 만든다. 설계 원본은 워커 8개를 이미지 1개와 `WORKER_ROLE` 환경변수로 나누자고 했지만, frame-encoder(PyTorch)와 chunk-processor(YOLO·FFmpeg)의 무거운 의존성이 가벼운 워커 이미지에 섞이지 않도록 유지하기로 했다(2026-11-02 결정).

## 결과

- 좋아지는 점: 분석 시점 AI 비용이 약 1/6로 준다. 외형 질의 정확도가 오른다. 재순위화 결과와 프레임 주석이 DB에 쌓여, 실제로 검색된 장면부터 검색 품질이 오른다.
- 감수할 점:
  - 검색 응답이 외부 VLM 지연에 묶인다. 타임아웃 후 인코더 순위로 응답하고, 서킷 브레이커와 사용자별 재순위화 상한을 둔다. 느리면 [아키텍처 v5](../architecture/architecture.md)의 "검색 지연 개선 방안"을 검토한다.
  - 이벤트 재현율이 탐지기에 묶인다. 후보 재현율과 판정 정밀도를 따로 재고, 정의 목록에 없는 사건은 검색 경로로 보완한다.
  - frame-encoder와 ai-gateway가 같은 SigLIP 2 버전을 써야 한다. 벡터마다 `embedding_model`을 기록하고 같은 모델 벡터만 검색한다.
- 후속 작업:
  - [서비스 카탈로그](../architecture/service-catalog.md)와 [아키텍처 v5](../architecture/architecture.md)를 이 결정 기준으로 갱신(이 ADR과 같은 PR)
  - ai 레포 `AGENTS.md`의 서비스 목록에서 vlm-worker를 frame-encoder로 교체
  - 이벤트 계약(`docs/contracts/events/`)과 분류 체계(`docs/contracts/taxonomy/`)는 각 기능 spec에서 이 토픽 목록 기준으로 작성
  - PoC에서 검색 단계별 지연(p50·p95)과 이미지 토큰 비용 실측
