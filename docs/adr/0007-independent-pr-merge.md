# ADR-0007 팀원 Approve 대기 없이 검증 후 PR을 직접 머지한다

## 맥락

기존 규칙은 명세 PR과 검사 예외에 팀원 승인을 요구했다. 사용자가 팀 정책 변경을 확정하고 앞으로 합의된 범위에서 명세·구현·검증·PR·머지를 연속 수행하도록 요청했다. 자기 PR은 GitHub Approve를 할 수 없어 별도 팀원 대기가 반복되었다.

## 결정 요인

- 명세 우선·계약 우선·테스트 절차 유지
- 팀원 부재에 의한 개발 대기 제거
- GitHub 보호 규칙과 필수 검사 유지

## 검토한 선택지

### 1. 팀원 Approve를 계속 기다린다

- 장점: 독립적인 사람의 검토가 있다.
- 단점: 합의된 작업도 팀원 부재 시 중단된다.

### 2. 자체 검토·필수 검사 후 직접 머지한다

- 장점: 합의된 범위의 작업을 연속 수행할 수 있다.
- 단점: 독립 리뷰가 기본 보장되지 않아 검증과 변경 근거를 PR에 명시해야 한다.

## 결정

선택지 2를 채택한다. 명세와 구현 PR은 별도 팀원 Approve 없이 자체 검토하고 필수 CI 및 GitHub 머지 조건을 충족하면 squash merge한다. 명세 작성·계획·계약·테스트 절차는 유지한다. Approved는 요구사항이 확정된 명세 상태이며 GitHub 승인 리뷰를 뜻하지 않는다. 실제 승인 리뷰가 없으면 있었다고 기록하지 않는다.

합의된 범위 내 커밋·push·PR·머지는 재확인 없이 수행한다. 요구사항 충돌·원인 불명의 테스트 실패는 원인과 필요한 결정을 사용자에게 알린다. 보호 규칙 우회·force push·검사 기준 완화는 금지한다. 인프라 apply·destroy의 GitHub Environment 실행 승인과 비용·범위 변경 확인은 이 정책으로 제거하지 않는다.

## 결과

- 공통 AGENTS.md·SDD 규칙·스킬·생성본을 갱신한다.
- 하위 레포의 sdd-plan은 팀원 승인이 아닌 확정·머지된 spec을 확인한다.
- 필수 CI 실패와 머지 충돌은 해결하기 전까지 머지하지 않는다.
- SPEC-004의 확정 요구사항은 변경 없이 Approved 상태로 정리한다.
