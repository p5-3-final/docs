# SPEC-032 플레이어 오버레이·클릭 조회·객체 질문·위험구역 편집 화면

> 이 문서에는 **무엇을, 왜**만 쓴다. 클래스, 테이블, 라이브러리 같은 구현 방법은 각 레포의 plan.md에 쓴다.

## 1. 배경과 목적

[아키텍처 개요](../../architecture/overview.md) 처리 흐름 12단계는 화면 동작을 이렇게 정한다.

- 화면을 클릭하면 analysis-api가 (t, x, y)로 트랙을 찾는다.
- 속성이 있으면 바로 돌려준다. 없으면 클래스와 박스를 먼저 돌려주고 속성 분석을 요청한 뒤 SSE로 채운다.
- 객체에 질문하면 같은 경로로 `object_question`을 요청한다(SPEC-024).

구역이 전제인 이벤트(위험구역 접근·체류·배회, 방호 미복구)는 구역을 정의해야 판정된다. 구역이 없으면 `unsupported_events`에 "구역 정의 없음"으로 남는다(overview 이벤트 정의 목록).

이 spec은 SPEC-031 영상 상세 화면의 플레이어에 다음을 더한다.

- 트랙 박스 오버레이와 클릭 조회
- 트랙 속성(보호구·역할·장비)
- 객체 자유 질문
- 위험구역 다각형 편집

analysis-api 공개 API는 다른 담당자 서비스이고, 이 spec이 overview "외부 API" 표대로 먼저 정한다(생산자 확인 필요).

## 2. 범위

### 포함

- 계약: `openapi/analysis-service.yaml` 0.4.0 공개 API 7개(오버레이, 클릭 조회, 트랙, 질문, 질문 결과, 구역 조회·바꾸기). 생산자 확인 필요.
- 플레이어 오버레이: 재생 시각에 맞춘 트랙 박스와 클래스 표시, 켜고 끄기, 이벤트 트랙 강조
- 클릭 조회: 일시정지 화면 클릭, 트랙 정보 패널, 속성 분석 대기와 SSE로 채우기, 실패 표시
- 객체 자유 질문: 질문 입력, 대기, SSE로 답 받기, 답할 수 없음·실패 표시, 질문 이력(화면이 열린 동안)
- 위험구역 편집: 정지 프레임 위 다각형 그리기·꼭짓점 옮기기·지우기, 이름·종류, 저장, 재분석 필요 안내

### 제외

- 재분석 요청 버튼: pipeline-service 공개 API를 정하는 이후 spec
- 마스크(분할) 표시: SPEC-026 제외 항목과 같음
- 여러 영상에 같은 구역 복사

## 3. 사용자 시나리오

### US-1 화면 속 객체 확인 (P1)

안전관리자로서 영상을 멈추고 사람을 누르면 그 사람이 안전모·조끼를 착용했는지 알고 싶다. 왜냐하면 이벤트가 나지 않은 사람도 확인해야 할 때가 있기 때문이다.

#### 인수 조건

- Given 속성이 이미 있는 트랙, When 박스 안을 누르면, Then 트랙 패널에 클래스, 등장 구간, 안전모·조끼·역할·장비·설명이 바로 보인다.
- Given 속성이 없는 트랙, When 누르면, Then 클래스와 박스가 먼저 보이고 "속성 분석 중"이 표시되며, `track.analyzed` 알림이 오면 속성으로 바뀐다.
- Given 박스가 없는 곳, When 누르면, Then "이 위치에서 찾은 객체가 없음"이 표시된다.

### US-2 객체에 질문 (P2)

안전관리자로서 "이 사람이 들고 있는 것은?"처럼 객체에 직접 묻고 싶다.

#### 인수 조건

- Given 트랙 패널, When 질문을 보내면, Then "답을 기다리는 중"이 보이고, 알림이 오면 답과 판정 상태가 보인다.
- Given 모델이 답할 수 없다고 한 질문(`answerable: false`), When 답이 오면, Then "화면만으로는 답할 수 없음"이 보인다.
- Given 질문 수 상한 초과(429), When 보내면, Then 잠시 뒤 다시 하라는 안내가 보인다.

### US-3 위험구역 정의 (P1)

안전관리자로서 영상 위에 위험구역을 그려 두고 싶다. 왜냐하면 구역이 있어야 위험구역 접근과 체류가 판정되기 때문이다.

#### 인수 조건

- Given 영상 상세의 구역 편집, When 꼭짓점 4개로 다각형을 그리고 이름·종류를 정해 저장하면, Then 구역이 저장되고 "다음 분석부터 반영됨(재분석 필요)" 안내가 보인다.
- Given 꼭짓점 2개 또는 자기 교차 다각형, When 저장하려 하면, Then 저장 버튼이 막히고 이유가 보인다.

### US-4 오버레이 (P2)

안전관리자로서 재생 중 탐지된 객체의 박스를 보고 싶다.

#### 인수 조건

- Given 오버레이 켬, When 재생하면, Then 현재 시각의 트랙 박스와 클래스가 영상 위에 보이고, 이벤트가 있는 트랙은 강조된다.

## 4. 요구사항

### 기능 요구사항 (EARS)

| ID | 요구사항 | 시나리오 |
| --- | --- | --- |
| R-1 | WHILE 오버레이가 켜져 있으면, THE frontend SHALL 재생 시각을 포함한 10초 구간의 오버레이를 미리 불러오고, 재생 시각에 가장 가까운 탐지 시각의 박스와 클래스를 영상 위에 그린다. | US-4 |
| R-2 | THE frontend SHALL 이벤트가 있는 트랙(`hasEvent`)의 박스를 다른 색과 굵기로 강조하고, 오버레이 켜고 끄기를 영상별로 기억하지 않고 기본 꺼짐으로 둔다. | US-4 |
| R-3 | WHEN 사용자가 일시정지한 영상 위를 누르면, THE frontend SHALL 누른 점을 프레임 크기로 나눈 좌표와 현재 시각으로 클릭 조회를 요청한다. | US-1 |
| R-4 | WHEN 클릭 조회가 트랙을 돌려주면, THE frontend SHALL 그 박스를 강조하고 트랙 패널에 클래스·등장 구간을 표시하며, 속성 상태가 `READY`이면 안전모·조끼·역할·장비·설명·판정 상태를, `REQUESTED`이면 "속성 분석 중"을, `FAILED`이면 실패 안내를 표시한다. | US-1 |
| R-5 | WHEN 열린 트랙 패널의 trackId로 `track.analyzed`(reason `click`·`event`) 알림이 오면, THE frontend SHALL 트랙을 다시 불러와 속성을 갱신한다. | US-1 |
| R-6 | IF 클릭 조회의 `hit`가 false이면, THEN THE frontend SHALL "이 위치에서 찾은 객체가 없음"을 표시하고 트랙 패널을 닫는다. | US-1 |
| R-7 | WHEN 사용자가 트랙 패널에서 1~200자 질문을 보내면, THE frontend SHALL 현재 시각과 함께 질문을 보내고 그 질문을 "답을 기다리는 중"으로 이력에 추가한다. | US-2 |
| R-8 | WHEN 그 질문의 requestId로 `track.analyzed`(reason `question`) 알림이 오면, THE frontend SHALL 질문 결과를 불러와 답과 판정 상태를 표시하고, `answerable`이 false이면 "화면만으로는 답할 수 없음"을, 실패면 실패 안내를 표시한다. | US-2 |
| R-9 | IF 질문 요청이 429를 돌려주면, THEN THE frontend SHALL 질문을 이력에 넣지 않고 잠시 뒤 다시 하라는 안내를 표시한다. | US-2 |
| R-10 | WHEN 사용자가 구역 편집을 열면, THE frontend SHALL 영상을 멈추고 현재 프레임 위에 저장된 구역 다각형을 이름·종류(위험구역·통로·일반)별 색으로 그린다. | US-3 |
| R-11 | THE frontend SHALL 구역 편집에서 클릭으로 꼭짓점 추가, 끌기로 꼭짓점 옮기기, 꼭짓점·구역 지우기, 이름·종류 입력을 제공하고, 꼭짓점 3~32개, 자기 교차 없음, 이름 1~100자·중복 없음, 구역 20개 이하를 만족할 때만 저장을 허용한다. | US-3 |
| R-12 | WHEN 사용자가 구역을 저장하면, THE frontend SHALL 구역 목록 전체를 보내고, 성공하면 "다음 분석부터 반영됨(재분석 필요)" 안내를 표시한다. 400 `ANALYSIS_ZONE_INVALID`이면 서버 이유를, 403이면 권한 없음 안내를 표시한다. | US-3 |
| R-13 | WHILE 영상의 구역 조회 결과가 `reanalysisNeeded: true`이면, THE frontend SHALL 영상 상세 요약 패널에 재분석이 필요하다는 안내를 표시한다. | US-3 |
| R-14 | THE frontend SHALL 오버레이 박스와 구역 다각형 좌표를 영상의 실제 표시 영역(레터박스 제외)에 맞춰 그리고, 창 크기가 바뀌면 다시 맞춘다. | US-1, US-3, US-4 |

### 비기능 요구사항

| ID | 요구사항 |
| --- | --- |
| NFR-1 | THE frontend SHALL 오버레이를 켠 재생에서 박스 그리기 때문에 프레임이 밀리지 않게 한 프레임 처리 시간을 16ms 안으로 유지한다(박스 50개 기준). |
