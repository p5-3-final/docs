# SPEC-005 영상 업로드 화면과 내 영상 목록

> 이 문서에는 **무엇을, 왜**만 쓴다. 클래스, 테이블, 라이브러리 같은 구현 방법은 각 레포의 plan.md에 쓴다.

## 1. 배경과 목적

SPEC-003으로 media-service의 업로드 자리 발급, 완료 확인, 목록, 삭제 API가 준비됐지만 브라우저에서 쓸 화면이 없다. 영상은 수백 MB에서 수 GB까지 크므로, 화면은 media-service가 준 주소로 파일을 저장소에 바로 올리고(100MB 이하는 한 번에, 넘으면 조각으로) 다 올린 뒤 완료를 요청해야 한다. 이 완료 요청이 `video.uploaded`를 거쳐 분석 파이프라인의 출발점이 된다.

이 spec은 SPEC-002가 빈 상태로 둔 영상 분석 화면에 영상 업로드와 내 영상 목록을 채운다.

## 2. 범위

### 포함

- 영상 분석 화면의 "영상 업로드" 버튼과 파일 끌어다 놓기로 파일 고르기(여러 개)
- 고른 파일을 대기열에 넣고 하나씩 순서대로 올리기, 파일마다 진행률 표시
- 100MB 이하 단일 업로드와 초과 멀티파트 업로드(SPEC-003 R-2, R-3, R-8)
- 업로드 전에 형식(mp4, mov, mkv, avi)과 크기(1바이트~5GB) 확인
- 실패한 요청의 자동 재시도와 "다시 시도", 업로드 취소
- 앱 안에서 다른 메뉴로 이동해도 업로드 계속, 업로드 중 창 닫기·새로고침 경고
- 영상 분석 화면의 내 영상 목록(최신순, 페이지 단위)과 영상 삭제
- media-service 오류 코드에 맞는 한국어 안내 문구
- 로컬 개발 환경에서 브라우저가 저장소에 직접 올릴 수 있는지 확인(ADR-0006 후속)

### 제외

- 영상 상세 화면, 재생, 썸네일: 분석 결과 화면 spec에서 다룬다.
- 새로고침이나 창을 다시 연 뒤 끝난 조각부터 이어 올리기
- 여러 파일 동시 업로드
- 정규화·분석 진행 상태의 실시간 갱신(notification-service spec)
- 운영 S3 버킷의 CORS 설정: infra 레포 작업이다(5. 영향 범위).
- 관리자가 다른 사용자의 영상을 보는 화면

## 3. 사용자 시나리오

### US-1 영상 올리기 (P1)

로그인한 사용자로서 내 컴퓨터의 영상 파일을 골라 올리고 싶다. 왜냐하면 영상을 분석하려면 먼저 올려야 하기 때문이다.

#### 인수 조건

- Given 영상 분석 화면, When "영상 업로드"로 100MB 이하 mp4 파일을 고르면, Then 진행률이 0%부터 100%까지 오르고 끝나면 목록 맨 위에 "업로드 완료" 상태로 보인다.
- Given 영상 분석 화면, When 100MB를 넘는 파일을 고르면, Then 같은 방식으로 진행률을 보며 올라가고 끝나면 "업로드 완료"가 된다.
- Given 파일 여러 개, When 한 번에 고르거나 끌어다 놓으면, Then 대기열에 들어가 하나씩 순서대로 올라간다.
- Given 지원하지 않는 형식이나 5GB를 넘는 파일, When 고르면, Then 그 파일은 올리지 않고 이유를 보여 준다.

### US-2 업로드 실패와 취소 (P1)

로그인한 사용자로서 네트워크가 잠깐 끊기거나 실수로 잘못된 파일을 골랐을 때 처음부터 다시 하지 않거나 바로 멈추고 싶다.

#### 인수 조건

- Given 업로드 중, When 조각 하나가 일시적으로 실패하면, Then 사용자가 모르게 다시 보내고 업로드가 이어진다.
- Given 다시 보내도 계속 실패함, When 재시도 횟수를 넘기면, Then 그 파일에 실패 안내와 "다시 시도" 버튼이 보이고 대기열의 다음 파일로 넘어간다.
- Given 올리고 있거나 기다리는 파일, When 취소하면, Then 그 파일의 업로드가 멈추고 목록에 남지 않는다.

### US-3 업로드 중 화면 이동 (P2)

로그인한 사용자로서 큰 영상을 올리는 동안 다른 메뉴를 둘러보고 싶다.

#### 인수 조건

- Given 업로드 중, When 다른 메뉴로 갔다가 영상 분석 화면으로 돌아오면, Then 업로드가 계속되고 있고 진행률이 보인다.
- Given 업로드 중, When 탭을 닫거나 새로고침하려 하면, Then 브라우저가 떠날지 묻는다.

### US-4 내 영상 보기 (P1)

로그인한 사용자로서 내가 올린 영상과 상태를 한눈에 보고 싶다.

#### 인수 조건

- Given 영상을 올린 사용자, When 영상 분석 화면에 들어오면, Then 내 영상이 최신순으로 파일 이름, 크기, 상태, 올린 시각과 함께 보인다.
- Given 영상이 20개를 넘음, When 다음 페이지로 가면, Then 그다음 영상들이 보인다.
- Given 올린 영상이 없음, When 영상 분석 화면에 들어오면, Then 영상이 없다는 안내와 업로드 버튼이 보인다.

### US-5 영상 삭제 (P2)

로그인한 사용자로서 필요 없는 영상을 지우고 싶다.

#### 인수 조건

- Given 내 영상, When 삭제를 누르고 확인하면, Then 목록에서 사라진다.
- Given 삭제 확인 창, When 취소하면, Then 아무것도 바뀌지 않는다.

## 4. 요구사항

### 기능 요구사항 (EARS)

| ID | 요구사항 | 시나리오 |
| --- | --- | --- |
| R-1 | WHEN 사용자가 영상 분석 화면에서 "영상 업로드" 버튼이나 끌어다 놓기로 파일을 하나 이상 고르면, THE frontend SHALL 고른 파일을 고른 순서대로 업로드 대기열에 넣는다. | US-1 |
| R-2 | IF 고른 파일의 확장자가 mp4, mov, mkv, avi가 아니면, THEN THE frontend SHALL 그 파일의 업로드 자리를 요청하지 않고 지원하지 않는 형식이라는 안내를 그 파일 옆에 표시한다. | US-1 |
| R-3 | IF 고른 파일의 크기가 0바이트이거나 5GB(5,368,709,120바이트)를 넘으면, THEN THE frontend SHALL 그 파일의 업로드 자리를 요청하지 않고 크기 제한 안내를 그 파일 옆에 표시한다. | US-1 |
| R-4 | WHILE 대기열에 올릴 파일이 있으면, THE frontend SHALL 한 번에 파일 하나씩, 대기열 순서대로 업로드 자리를 요청하고 올린다. | US-1 |
| R-5 | WHEN media-service가 단일 업로드(`SINGLE`) 방법을 주면, THE frontend SHALL 받은 `fields`를 모두 담고 파일을 마지막에 넣은 POST 폼으로 받은 `url`에 파일을 올린다. | US-1 |
| R-6 | WHEN media-service가 멀티파트 업로드(`MULTIPART`) 방법을 주면, THE frontend SHALL 파일을 `partSizeBytes` 크기의 조각으로 나눠 조각마다 받은 주소로 PUT하고 응답의 `ETag`를 모은다. | US-1 |
| R-7 | WHEN 파일의 모든 바이트를 저장소에 올리면, THE frontend SHALL 업로드 완료를 요청하고(멀티파트면 조각 번호와 `ETag` 목록을 담아) 응답의 상태로 목록을 갱신한다. | US-1 |
| R-8 | WHILE 파일을 올리는 중이면, THE frontend SHALL 그 파일의 진행률을 올린 바이트 비율(%)로 표시한다. | US-1 |
| R-9 | IF 저장소로 보낸 업로드 요청(단일 POST 또는 조각 PUT)이 네트워크 오류나 5xx로 실패하면, THEN THE frontend SHALL 같은 요청을 최대 3번까지 다시 보낸다. | US-2 |
| R-10 | IF 재시도까지 실패하거나 업로드 자리 요청·완료 요청이 실패하면, THEN THE frontend SHALL 그 파일을 실패로 표시하고 오류 안내와 "다시 시도" 버튼을 보여 준 뒤 대기열의 다음 파일로 넘어간다. | US-2 |
| R-11 | WHEN 사용자가 실패한 파일의 "다시 시도"를 누르면, THE frontend SHALL 그 파일을 대기열 끝에 넣고 새 업로드 자리를 받아 처음부터 올린다. | US-2 |
| R-12 | WHEN 사용자가 기다리거나 올리고 있는 파일을 취소하면, THE frontend SHALL 그 파일의 업로드를 멈추고 대기열에서 빼며, 이미 업로드 자리를 받았다면 그 영상의 삭제를 요청한다. | US-2 |
| R-13 | WHILE 업로드 중인 파일이 있으면, THE frontend SHALL 앱 안의 다른 화면으로 이동해도 업로드를 계속하고, 영상 분석 화면으로 돌아오면 대기열과 진행률을 다시 표시한다. | US-3 |
| R-14 | WHILE 업로드 중이거나 기다리는 파일이 있으면, THE frontend SHALL 사용자가 탭을 닫거나 새로고침하려 할 때 브라우저의 떠나기 확인을 띄운다. | US-3 |
| R-15 | WHEN 사용자가 영상 분석 화면에 들어오면, THE frontend SHALL 내 영상을 최신순으로 20개씩 파일 이름, 크기, 상태, 올린 시각과 함께 표시하고 페이지를 넘길 수 있게 한다. | US-4 |
| R-16 | THE frontend SHALL 영상 상태(`UPLOADING`, `UPLOADED`, `EXPIRED`, `NORMALIZING`, `READY`, `REJECTED`)마다 정한 한국어 이름을 표시한다. | US-4 |
| R-17 | WHILE 영상이 `UPLOADING`이고 지금 이 화면의 대기열에서 올리고 있는 파일이 아니면, THE frontend SHALL 그 영상에 업로드가 끝나지 않았고 24시간 뒤 만료된다는 안내를 표시한다. | US-4 |
| R-18 | WHILE 내 영상이 없고 대기열도 비어 있으면, THE frontend SHALL 올린 영상이 없다는 안내와 업로드 버튼을 표시한다(SPEC-002 R-16 대체). | US-4 |
| R-19 | WHEN 사용자가 목록에서 영상의 삭제를 누르면, THE frontend SHALL 파일 이름을 보여 주는 확인 창을 띄우고, 확인하면 삭제를 요청한 뒤 목록에서 뺀다. | US-5 |
| R-20 | IF 삭제 응답이 `MEDIA_VIDEO_NOT_FOUND`이면, THEN THE frontend SHALL 이미 없는 영상이라는 안내를 표시하고 목록을 다시 불러온다. | US-5 |
| R-21 | WHERE 로컬 개발 환경(docs 레포 local compose)인 경우, THE 로컬 저장소(SeaweedFS) SHALL frontend 주소(`http://localhost:5173`, `http://localhost:3000`)에서 오는 업로드 POST·PUT을 허용하고 응답의 `ETag` 헤더를 브라우저가 읽을 수 있게 한다. | US-1 |

### 비기능 요구사항

| ID | 요구사항 |
| --- | --- |
| NFR-1 | THE frontend SHALL 영상 파일 바이트를 api-gateway나 media-service로 보내지 않고 media-service가 준 저장소 주소로만 보낸다. |
| NFR-2 | THE frontend SHALL 업로드 주소(서명 포함)와 업로드 폼 값을 브라우저 저장소(localStorage, sessionStorage, IndexedDB)에 저장하거나 콘솔에 출력하지 않는다. |
| NFR-3 | THE frontend SHALL media-service 오류 응답의 `code`(`MEDIA_FILE_SIZE_INVALID`, `MEDIA_UNSUPPORTED_FORMAT`, `MEDIA_UPLOAD_INCOMPLETE`, `MEDIA_INVALID_STATE`, `MEDIA_VIDEO_NOT_FOUND`, `MEDIA_INVALID_REQUEST`)마다 정한 한국어 문구를 표시하고, 정하지 않은 `code`에는 공통 문구를 표시한다(SPEC-002 NFR-3). |
| NFR-4 | THE frontend SHALL 업로드 진행률 표시를 1초에 한 번 이상 갱신한다. |
| NFR-5 | THE frontend SHALL 파일 고르기, 업로드 취소, 다시 시도, 삭제와 확인 창을 키보드만으로 조작할 수 있게 하고, 진행률과 완료·실패를 화면 낭독기가 읽을 수 있게 한다. |
| NFR-6 | THE frontend SHALL 가로 360px 이상의 모든 화면 너비에서 가로 스크롤 없이 업로드 대기열과 내 영상 목록을 표시한다. |

## 7. 성공 지표

- 로컬 compose와 frontend로 1MB·110MB 파일을 브라우저에서 올려 "업로드 완료"가 되고 Kafka에 `video.uploaded`가 발행되는 것을 시연할 수 있다.
- 파일 여러 개를 한 번에 골라 순서대로 올라가는 것, 조각 하나를 실패시켜도 자동 재시도로 끝나는 것을 시연할 수 있다.
- 휴대폰(360px)과 데스크톱에서 업로드와 목록·삭제를 쓸 수 있다.

## 8. 미결 사항

- 없음. 결정 사항(2026-11-03 사용자 확인)
  - 업로드와 내 영상 목록은 영상 분석 화면에 둔다. 상세 화면은 만들지 않고 목록 행에 정보를 보여 준다.
  - 파일은 여러 개 고를 수 있고, 한 번에 하나씩 순서대로 올린다.
  - 실패한 요청은 자동으로 3번까지 다시 보내고, 그래도 실패하면 "다시 시도"로 처음부터 올린다. 새로고침 뒤 이어 올리기는 하지 않는다.
  - 앱 안의 화면 이동에도 업로드를 계속하고, 창 닫기·새로고침은 경고한다.
