# SPEC-033 검색 화면(문장·이미지 장면 찾기, 주석 클립)과 영상 질문(Video RAG)

> 이 문서에는 **무엇을, 왜**만 쓴다. 클래스, 테이블, 라이브러리 같은 구현 방법은 각 레포의 plan.md에 쓴다.

## 1. 배경과 목적

[아키텍처 v5](../../architecture/architecture.md) "검색 경로"는 search-service가 결과마다 이동 시각(시작 2초 전), 유사도, 쓴 인코더·해석 방법을 돌려준다고 정한다. 상위 3개 구간에는 bbox 주석 클립이 비동기로 붙는다(SPEC-026). 화면이 지켜야 할 규칙도 있다.

- 점수는 "유사도"로만 표시한다.
- 결과 화면에 "장면 외형 기준 검색"임을 밝힌다.
- 정밀 검색에서 기준 점수를 넘은 결과가 없으면 "찾지 못함"으로 표시한다.
- Video RAG는 근거에서만 답하고, 모델이 없거나 시간이 초과되면 답 없이 근거만 준다.
- 질의 로그의 이동·재생과 맞음·틀림이 사전 보강과 Golden Set 질의 후보가 된다.

이 spec은 사이드바 "검색" 화면과 영상 상세의 "영상에 질문" 패널을 만든다. search-service 공개 API는 다른 담당자 서비스이고, 이 spec이 overview "외부 API" 표대로 먼저 정한다(생산자 확인 필요).

## 2. 범위

### 포함

- 계약: `openapi/search-service.yaml` 0.1.0 공개 API 6개(영상 안 검색, 전체 검색, 이미지 검색, 영상 질문, 이동·재생·맞음·틀림 기록, 주석 클립). 생산자 확인 필요.
- "검색" 화면
  - 질의 입력(1~200자), 범위(이 영상·내 영상 전체), 정밀 검색 켜기, 이미지 올려 찾기
  - 결과 목록: 썸네일, 영상 이름, 구간, 유사도, 찾은 경로, 해석 방법·대상어
  - 결과 상태 안내: "찾지 못함", 축소 응답 안내, 재사용 결과 표시, "장면 외형 기준 검색" 표시
  - 결과 누르면 영상 상세를 이동 시각으로 열기, 맞음·틀림
- 주석 클립: SSE `grounding.completed`로 상태 갱신, 준비되면 클립 재생과 대상어 색 범례·프레임별 객체 수
- 영상 상세 "영상에 질문" 패널: 질문, 답·판정 상태, 근거 구간·관련 이벤트로 이동, 한계 표시, 답 없음 안내

### 제외

- 검색 결과 저장·공유, 질의 자동 완성
- 정밀 검색 상한 설정 화면(운영 설정)
- 질의 로그 화면(품질 화면 SPEC-035에서 다룰지 이후 결정)

## 3. 사용자 시나리오

### US-1 문장으로 장면 찾기 (P1)

안전관리자로서 "안전모 안 쓴 작업자"라고 입력해 그 장면으로 바로 가고 싶다. 왜냐하면 영상을 처음부터 넘겨 보며 찾는 데 시간이 많이 들기 때문이다.

#### 인수 조건

- Given 분석이 끝난 영상, When 영상 범위로 검색하면, Then 결과가 유사도 순으로 썸네일·구간·유사도와 함께 보이고 "장면 외형 기준 검색" 안내가 보인다.
- Given 결과, When 하나를 누르면, Then 그 영상 상세가 시작 2초 전 시각으로 열린다.
- Given 정밀 검색에서 기준을 넘은 결과가 없음(`notFound`), When 결과를 보면, Then "찾지 못함"이 먼저 보이고 아래에 참고 결과가 흐리게 보인다.
- Given 정밀 검색 상한 초과로 인코더 순위만 받음(`degraded`), When 결과를 보면, Then 정밀 검색을 하지 못했다는 안내가 보인다.

### US-2 주석 클립 (P1)

안전관리자로서 상위 결과에서 대상이 박스로 표시된 클립을 보고 싶다.

#### 인수 조건

- Given 상위 3개 결과(주석 `REQUESTED`), When `grounding.completed` READY 알림이 오면, Then 그 결과에 "주석 클립 보기"가 생기고 누르면 박스가 그려진 클립이 재생된다.
- Given FAILED 알림, When 받으면, Then 그 결과의 주석 자리에 "주석을 만들지 못함"이 보인다.

### US-3 이미지로 찾기 (P2)

안전관리자로서 장비 사진을 올려 비슷한 장면을 찾고 싶다.

#### 인수 조건

- Given 5MB 이하 jpg, When 올리면, Then 비슷한 장면이 유사도 순으로 보인다.
- Given 5MB를 넘거나 다른 형식, When 고르면, Then 올리지 않고 이유가 보인다.

### US-4 영상에 질문 (P1)

안전관리자로서 "방호벽은 언제 치워졌나요?"처럼 영상에 묻고, 근거 장면을 함께 보고 싶다.

#### 인수 조건

- Given 분석이 끝난 영상, When 질문하면, Then 답, 판정 상태, 근거 구간·관련 이벤트가 보이고 근거를 누르면 그 시각으로 이동한다.
- Given 모델 미설정·시간 초과(`answer: null`), When 결과를 받으면, Then "답을 만들지 못했고 근거만 보여 줌" 안내와 근거가 보인다.

### US-5 맞음·틀림 (P2)

안전관리자로서 잘못된 결과를 틀림으로 표시하고 싶다. 그래야 다음 검색에서 그 결과가 줄어든다.

#### 인수 조건

- Given 결과, When "틀림"을 누르면, Then 표시가 바뀌고 기록 요청이 한 번 간다.

## 4. 요구사항

### 기능 요구사항 (EARS)

| ID | 요구사항 | 시나리오 |
| --- | --- | --- |
| R-1 | WHEN 사용자가 1~200자 질의로 영상 범위 검색을 하면, THE frontend SHALL 정밀 검색 선택값과 함께 영상 안 검색을 요청하고, 결과를 받은 순서대로 썸네일·구간·"유사도" 값·찾은 경로(시각·텍스트·이미지)를 표시한다. | US-1 |
| R-2 | THE frontend SHALL 결과 위에 해석된 대상어와 해석 방법, "장면 외형 기준 검색" 안내, 재사용 결과이면 그 표시를 보여 준다. | US-1 |
| R-3 | IF 결과의 `notFound`가 true이면, THEN THE frontend SHALL "찾지 못함"을 먼저 표시하고 결과는 참고용으로 흐리게 표시한다. | US-1 |
| R-4 | IF 결과의 `degraded`가 있으면, THEN THE frontend SHALL 이유(재순위화 시간 초과·장애·정밀 검색 상한·AI 사용 불가)에 맞는 안내를 결과 위에 표시한다. | US-1 |
| R-5 | WHEN 결과의 groundingId로 `grounding.completed` 알림이 오면, THE frontend SHALL READY이면 주석 클립 정보를 불러와 "주석 클립 보기"를 표시하고, FAILED이면 "주석을 만들지 못함"을 표시한다. 주석 상태가 `NONE`인 결과에는 주석 자리를 두지 않는다. | US-2 |
| R-6 | WHEN 사용자가 "주석 클립 보기"를 누르면, THE frontend SHALL 클립을 재생하고 대상어별 색 범례와 프레임별 객체 수를 함께 표시한다. | US-2 |
| R-7 | WHERE 범위가 "내 영상 전체"이면, THE frontend SHALL 전체 검색을 요청하고 정밀 검색 선택을 끄며, 결과마다 영상 이름을 표시한다. | US-1 |
| R-8 | WHEN 사용자가 jpg·png·webp 5MB 이하 이미지를 고르면, THE frontend SHALL 범위(영상이면 sourceId)와 함께 이미지 검색을 요청하고 R-1처럼 결과를 표시한다. 형식·크기를 벗어나면 요청하지 않고 이유를 표시한다. | US-3 |
| R-9 | WHEN 사용자가 영상 상세의 "영상에 질문"에서 1~200자 질문을 보내면, THE frontend SHALL 영상 질문을 요청하고 답, 판정 상태, 근거 구간, 관련 이벤트, 한계를 표시하며, 근거나 이벤트를 누르면 플레이어를 그 `seekMs`로 옮긴다. | US-4 |
| R-10 | IF 영상 질문 결과의 `answer`가 null이면, THEN THE frontend SHALL "답을 만들지 못했고 근거만 보여 줌" 안내와 근거를 표시한다. | US-4 |
| R-11 | WHEN 사용자가 결과를 눌러 이동하거나 이동한 영상을 5초 넘게 재생하거나 맞음·틀림을 누르면, THE frontend SHALL 그 결과의 momentId로 `jumped`·`played`(재생 길이)·`correct`·`incorrect`를 한 번씩 기록한다. | US-5 |
| R-12 | WHEN 사용자가 결과를 누르면, THE frontend SHALL 그 영상 상세를 결과의 `seekMs`로 열고, 검색 화면으로 돌아오면 질의와 결과를 다시 요청하지 않고 보여 준다. | US-1 |
| R-13 | IF 검색 API가 400이면, THEN THE frontend SHALL 질의 입력 옆에 이유를 표시하고, 404 `SEARCH_NOT_INDEXED`이면 "아직 검색할 수 있게 준비되지 않음"을, 5xx·네트워크 오류면 다시 시도 버튼을 표시한다. | US-1 |

### 비기능 요구사항

| ID | 요구사항 |
| --- | --- |
| NFR-1 | THE frontend SHALL 결과 50개를 응답 뒤 200ms 안에 그리고, 썸네일은 화면에 보이는 것만 불러온다. |
| NFR-2 | THE frontend SHALL 검색 질의와 서명 주소를 URL 이외의 브라우저 저장소에 남기지 않는다. |
