# SPEC-034 작업 세션·분석 이력 화면과 학습용 보존 설정 화면

> 이 문서에는 **무엇을, 왜**만 쓴다. 클래스, 테이블, 라이브러리 같은 구현 방법은 각 레포의 plan.md에 쓴다.

## 1. 배경과 목적

작업 세션(SPEC-017)은 영상 여러 개를 작업 하나(작업 전·중·후)로 묶는다. aggregator는 세션 직전 영상의 마지막 상태로 다음 영상을 시작한다. 그래서 "작업 전 영상에 있던 방호벽이 작업 후 영상에 없다"를 찾을 수 있다(SPEC-027 R-5, SPEC-028 R-6). 학습용 보존 동의(SPEC-018)는 계정 기본값, 영상별 동의, 보존 중인 삭제 영상의 철회로 이루어진다. 두 기능 모두 media-service API는 있지만 화면이 없다.

이 spec은 다음 세 가지를 만든다. 쓰는 API는 모두 기존 계약(media-service, SPEC-031의 analysis-api 공개 API)이라 계약 변경은 없다.

- 사이드바 "분석 이력" 메뉴: 작업 세션 목록·상세
  - 세션 상세는 역할별 영상과 각 영상의 분석 요약, 이어 온 위험, 재고 변화를 보여 준다.
- 업로드할 때 세션·역할 고르기
- "설정" 메뉴: 학습용 보존 기본값과 보존 중인 삭제 영상, 그리고 영상 상세의 보존 동의 바꾸기

## 2. 범위

### 포함

- "분석 이력" 화면: 내 작업 세션 목록(최신순), 세션 만들기(이름·현장·구역)
- 세션 상세
  - 역할(작업 전·중·후)별 영상 목록과 영상마다 분석 요약(상태, 확정 이벤트 수, 끝까지 활성인 위험 수)
  - 세션 흐름 요약: 세션에서 이어 온 위험, 방호 미복구·물건 제거·이동 이벤트를 시간순으로
- 업로드 화면에서 세션과 역할 고르기(새 세션 만들기 포함). 고른 값은 업로드 자리 요청에 싣는다.
- "설정" 화면: 학습용 보존 기본값 바꾸기, 보존 중인 삭제 영상 목록·하나 철회·전체 철회
- 영상 상세의 학습용 보존 동의 바꾸기

### 제외

- 세션 이름 바꾸기·지우기, 영상의 세션·역할 바꾸기: SPEC-017에서 지원하지 않는다.
- 세션 단위 재분석
- 계정 정보·비밀번호 바꾸기 화면

## 3. 사용자 시나리오

### US-1 작업 전후 비교 (P1)

안전관리자로서 방호벽 교체 작업의 작업 전·후 영상을 묶어, 작업 후에 방호 시설이 돌아왔는지 한 화면에서 보고 싶다. 왜냐하면 미복구는 작업이 끝난 뒤 사고로 이어지기 때문이다.

#### 인수 조건

- Given 작업 전·후 영상이 든 세션, When 세션 상세를 열면, Then 역할별로 영상이 나오고 영상마다 분석 상태와 확정 이벤트 수, 끝까지 활성인 위험 수가 보인다.
- Given 작업 후 영상에 `barrier_not_restored` 확정 이벤트, When 세션 흐름 요약을 보면, Then 그 이벤트가 "방호 미복구"로 보이고 누르면 그 영상 상세가 이벤트 시각으로 열린다.
- Given 작업 전 영상에서 이어 온 활성 위험, When 세션 흐름 요약을 보면, Then "이전 영상에서 이어짐" 표시와 함께 보인다.

### US-2 세션에 영상 올리기 (P1)

안전관리자로서 영상을 올릴 때 세션과 역할을 고르고 싶다.

#### 인수 조건

- Given 업로드 화면, When 세션 "3번 라인 방호벽 교체"와 역할 "작업 후"를 고르고 파일을 올리면, Then 그 영상이 세션 상세의 작업 후 칸에 나온다.
- Given 업로드 화면, When "새 세션"을 고르고 이름을 넣으면, Then 세션이 만들어지고 그 세션으로 올라간다.

### US-3 학습용 보존 설정 (P2)

사용자로서 내 영상을 학습용으로 보존할지 기본값과 영상별로 정하고, 보존 중인 삭제 영상은 언제든 철회하고 싶다.

#### 인수 조건

- Given 설정 화면, When 보존 기본값을 켜면, Then 그 뒤에 만드는 영상의 동의가 기본으로 켜진다.
- Given 영상 상세, When 보존 동의를 끄면, Then 그 영상의 동의가 꺼진다.
- Given 보존 중인 삭제 영상 2개, When "전체 철회"를 누르고 확인하면, Then 목록이 빈다.

## 4. 요구사항

### 기능 요구사항 (EARS)

| ID | 요구사항 | 시나리오 |
| --- | --- | --- |
| R-1 | WHEN 사용자가 "분석 이력" 메뉴에 들어오면, THE frontend SHALL 내 작업 세션을 최신순으로 20개씩 이름·현장·구역·만든 시각과 함께 표시하고, 세션이 없으면 안내와 "세션 만들기"를 표시한다. | US-1 |
| R-2 | WHEN 사용자가 이름(필수)·현장·구역으로 세션을 만들면, THE frontend SHALL 세션 만들기를 요청하고 성공하면 그 세션 상세로 이동한다. 400이면 입력 옆에 이유를 표시한다. | US-2 |
| R-3 | WHEN 사용자가 세션을 열면, THE frontend SHALL 세션 상세를 불러와 영상을 역할(작업 전 → 작업 중 → 작업 후) 칸에 받은 순서대로 표시하고, 영상마다 SPEC-031 요약 API로 분석 상태·확정 이벤트 수·활성 위험 수를 표시한다. | US-1 |
| R-4 | THE frontend SHALL 세션 흐름 요약에 세션 영상들의 이어 온 위험(`carriedOver`)과 유형 `barrier_not_restored`·`object_removed`·`object_moved`의 확정 이벤트를 영상 역할 순, 영상 안 시각 순으로 표시하고, 누르면 그 영상 상세를 그 이벤트(또는 위험 시작 시각)로 연다. | US-1 |
| R-5 | WHILE 세션 영상 중 분석이 끝나지 않은 영상이 있으면, THE frontend SHALL 세션 흐름 요약 위에 "분석이 끝나지 않은 영상이 있어 비교가 완전하지 않음"을 표시한다. | US-1 |
| R-6 | THE frontend SHALL 업로드 화면에 세션 고르기(없음·내 세션·새 세션)와 역할 고르기(작업 전·중·후)를 두고, 세션을 고르면 역할을 필수로 받으며, 고른 값을 업로드 자리 요청의 `sessionId`·`role`에 싣는다. | US-2 |
| R-7 | WHEN 사용자가 업로드 화면에서 "새 세션"을 고르고 이름을 넣으면, THE frontend SHALL 첫 파일의 업로드 자리를 요청하기 전에 세션을 만들고 그 ID를 쓴다. | US-2 |
| R-8 | THE frontend SHALL 세션 상세에서 "이 세션에 영상 올리기"를 누르면 그 세션이 골라진 업로드 화면을 연다. | US-2 |
| R-9 | WHEN 사용자가 "설정" 메뉴에 들어오면, THE frontend SHALL 학습용 보존 기본값을 불러와 켜고 끄기로 표시하고, 바꾸면 저장한 뒤 "이후에 올리는 영상에 적용됨"을 표시한다. | US-3 |
| R-10 | THE frontend SHALL 설정 화면에 보존 중인 삭제 영상을 영상 ID·삭제 시각·보존 만료 시각(`retainUntil`)과 함께 쪽 나눠 표시하고, 하나 철회와 전체 철회를 확인 창 뒤에 요청한다. | US-3 |
| R-11 | THE frontend SHALL 영상 상세에 학습용 보존 동의를 켜고 끄기로 표시하고(소유자일 때만), 바꾸면 저장한 뒤 "영상을 지울 때의 값이 적용됨"을 표시한다. | US-3 |
| R-12 | IF media API가 404를 돌려주면, THEN THE frontend SHALL 세션·영상을 찾을 수 없다는 안내를 표시하고, 5xx·네트워크 오류면 다시 시도 버튼을 표시한다. | US-1 |

### 비기능 요구사항

| ID | 요구사항 |
| --- | --- |
| NFR-1 | THE frontend SHALL 영상 20개인 세션 상세에서 영상별 요약 요청을 동시에 최대 4개까지만 보낸다. |
| NFR-2 | THE frontend SHALL 세션 상세를 응답 뒤 300ms 안에 그리고, 요약은 도착하는 대로 채운다. |
