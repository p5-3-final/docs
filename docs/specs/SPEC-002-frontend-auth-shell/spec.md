# SPEC-002 인증 화면과 앱 기본 레이아웃

> 이 문서에는 **무엇을, 왜**만 쓴다. 클래스, 테이블, 라이브러리 같은 구현 방법은 각 레포의 plan.md에 쓴다.

## 1. 배경과 목적

SPEC-001로 가입, 로그인, 로그인 유지, 로그아웃 API가 준비됐지만 브라우저에서 쓸 화면이 없다. 사용자가 브라우저에서 가입하고 로그인한 뒤 앱에 들어갈 수 있어야, 이후 영상 업로드·분석·검색 화면을 그 위에 올릴 수 있다.

이 spec은 인증 화면과, 이후 기능 화면이 들어갈 앱 기본 레이아웃(사이드바, 상단 바)을 정한다. 화면 디자인은 팀이 공유한 "AI 안전 관제" 다크 테마 시안을 따른다.

## 2. 범위

### 포함

- 가입 화면, 로그인 화면
- 로그인 유지: 접근 토큰 만료와 페이지 새로고침 뒤에도 다시 로그인하지 않고 계속 쓰기
- 로그아웃
- 로그인한 사용자의 내 정보(닉네임, 이메일, 역할) 표시
- 로그인해야 쓸 수 있는 화면의 접근 제한
- 앱 기본 레이아웃: 사이드바 메뉴, 상단 바(서비스 이름, 사용자 메뉴)
- 사이드바의 기능 메뉴(영상 분석, 이벤트, 검색, 분석 이력, 설정)와 각 메뉴의 "준비 중" 화면. 실제 화면은 각 기능 spec에서 채운다.
- 로그인 후 첫 화면인 영상 분석 빈 화면
- 모바일(가로 360px)부터 데스크톱까지 반응형 레이아웃
- SPEC-001 오류 코드에 맞는 한국어 안내 문구

### 제외

- 영상 업로드, 분석 결과, 이벤트, 검색 화면의 실제 기능 (각 기능 spec)
- 실시간 알림 연결 (notification-service가 생길 때 별도 spec)
- 비밀번호 찾기·변경, 회원 탈퇴, 소셜 로그인 (SPEC-001에서 제외)
- 관리자 전용 화면

## 3. 사용자 시나리오

### US-1 가입 (P1)

처음 방문한 사용자로서 브라우저에서 이메일로 가입하고 싶다. 왜냐하면 내 계정으로 영상을 분석하고 싶기 때문이다.

**인수 조건**

- Given 가입 화면, When 올바른 이메일·비밀번호·닉네임으로 가입하면, Then 계정이 만들어지고 가입 완료 안내와 함께 로그인 화면으로 이동하며, 이메일 칸에 가입한 이메일이 채워져 있다.
- Given 입력값이 규칙에 맞지 않음, When 가입을 누르면, Then 서버에 보내기 전에 어떤 칸이 왜 틀렸는지 보인다.
- Given 이미 가입된 이메일, When 가입하면, Then 이미 가입된 이메일이라는 안내를 본다.

### US-2 로그인 (P1)

가입한 사용자로서 로그인해서 앱에 들어가고 싶다.

**인수 조건**

- Given 로그인 화면, When 올바른 이메일과 비밀번호로 로그인하면, Then 앱 첫 화면(영상 분석)으로 들어가고 상단 바에 내 닉네임이 보인다.
- Given 틀린 이메일이나 비밀번호, When 로그인하면, Then 무엇이 틀렸는지 구분하지 않는 안내를 본다.
- Given 잠긴 계정이나 요청 수 초과, When 로그인하면, Then 잠시 후 다시 시도하라는 안내를 본다.
- Given 로그인하지 않은 사용자, When 앱 화면 주소로 바로 들어가면, Then 로그인 화면으로 이동하고 로그인 뒤 원래 주소로 돌아간다.

### US-3 로그인 유지 (P1)

로그인한 사용자로서 접근 토큰이 만료되거나 페이지를 새로고침해도 다시 로그인하지 않고 계속 쓰고 싶다.

**인수 조건**

- Given 로그인한 상태, When 페이지를 새로고침하면, Then 로그인 상태가 유지된다.
- Given 접근 토큰이 만료됨, When 화면에서 요청을 보내면, Then 사용자가 모르게 새 토큰을 받고 요청이 이어진다.
- Given 재발급까지 실패함, When 요청을 보내면, Then 로그인 화면으로 이동한다.

### US-4 내 정보와 로그아웃 (P1)

로그인한 사용자로서 지금 어떤 계정으로 들어와 있는지 확인하고, 다 쓰면 로그아웃하고 싶다.

**인수 조건**

- Given 로그인한 상태, When 사용자 메뉴를 열면, Then 닉네임, 이메일, 역할이 보인다.
- Given 로그인한 상태, When 로그아웃하면, Then 로그인 화면으로 이동하고 새로고침해도 로그인되지 않는다.

### US-5 앱 둘러보기 (P2)

로그인한 사용자로서 앱에 어떤 기능이 있는지 메뉴로 보고 이동하고 싶다. 왜냐하면 기능이 하나씩 추가될 때 같은 자리에서 찾을 수 있어야 하기 때문이다.

**인수 조건**

- Given 로그인한 상태, When 앱에 들어오면, Then 영상 분석 화면이 열리고 분석한 영상이 아직 없다는 안내가 보인다.
- Given 로그인한 상태, When 사이드바에서 아직 준비되지 않은 메뉴를 누르면, Then 그 메뉴가 선택된 상태로 준비 중이라는 안내가 보인다.
- Given 휴대폰 화면, When 앱을 쓰면, Then 가로 스크롤 없이 보이고 메뉴는 버튼으로 열고 닫는다.

## 4. 요구사항

### 기능 요구사항 (EARS)

| ID | 요구사항 | 시나리오 |
| --- | --- | --- |
| R-1 | WHEN 가입 요청이 성공하면, THE frontend SHALL 가입 완료 안내와 함께 로그인 화면으로 이동하고 이메일 칸에 가입한 이메일을 채운다. | US-1 |
| R-2 | IF 가입 입력값이 SPEC-001의 규칙(이메일 형식, 비밀번호 8~64자·영문과 숫자 포함, 닉네임 2~20자·한글·영문·숫자)에 맞지 않으면, THEN THE frontend SHALL 가입을 요청하지 않고 틀린 입력 칸 옆에 이유를 표시한다. | US-1 |
| R-3 | IF 가입 응답이 `AUTH_EMAIL_DUPLICATED`이면, THEN THE frontend SHALL 이메일 칸에 이미 가입된 이메일이라는 안내를 표시한다. | US-1 |
| R-4 | WHEN 사용자가 로그인 화면에서 로그인에 성공하면, THE frontend SHALL 영상 분석 화면으로 이동하고 상단 바에 사용자 닉네임을 표시한다. | US-2 |
| R-5 | IF 로그인 응답이 `AUTH_INVALID_CREDENTIALS`이면, THEN THE frontend SHALL 이메일과 비밀번호 중 무엇이 틀렸는지 구분하지 않는 안내를 표시한다. | US-2 |
| R-6 | IF 로그인 응답이 `AUTH_ACCOUNT_LOCKED` 또는 `GATEWAY_RATE_LIMITED`이면, THEN THE frontend SHALL 잠시 후 다시 시도하라는 안내를 표시한다. | US-2 |
| R-7 | WHEN 로그인하지 않은 사용자가 로그인해야 쓸 수 있는 화면 주소로 들어오면, THE frontend SHALL 로그인 화면으로 이동하고, 로그인에 성공하면 처음 요청한 주소로 이동한다. | US-2 |
| R-8 | WHEN 로그인한 사용자가 페이지를 새로고침하거나 새 탭에서 앱을 열면, THE frontend SHALL 재발급 토큰으로 로그인 상태를 되살린다. | US-3 |
| R-9 | WHEN 요청이 접근 토큰 만료(`AUTH_TOKEN_EXPIRED`)로 거절되면, THE frontend SHALL 접근 토큰을 재발급받고 같은 요청을 한 번 다시 보낸다. | US-3 |
| R-10 | IF 접근 토큰 재발급이 실패하면, THEN THE frontend SHALL 로그인 상태를 지우고 로그인 화면으로 이동한다. | US-3 |
| R-11 | WHEN 로그인한 사용자가 사용자 메뉴를 열면, THE frontend SHALL 닉네임, 이메일, 역할을 표시한다. | US-4 |
| R-12 | WHEN 로그인한 사용자가 로그아웃하면, THE frontend SHALL 로그아웃을 요청하고 로그인 상태를 지운 뒤 로그인 화면으로 이동한다. | US-4 |
| R-13 | THE frontend SHALL 로그인 화면과 가입 화면을 제외한 모든 화면을 사이드바와 상단 바가 있는 앱 기본 레이아웃 안에 표시한다. | US-2, US-5 |
| R-14 | THE frontend SHALL 사이드바에 영상 분석, 이벤트, 검색, 분석 이력, 설정 메뉴를 표시하고, 현재 화면의 메뉴를 선택된 상태로 표시한다. | US-5 |
| R-15 | WHEN 사용자가 아직 기능이 없는 메뉴로 이동하면, THE frontend SHALL 그 메뉴 이름과 준비 중이라는 안내를 표시한다. | US-5 |
| R-16 | WHILE 사용자가 분석한 영상이 없으면, THE frontend SHALL 영상 분석 화면에 분석한 영상이 없다는 안내를 표시한다. | US-5 |

### 비기능 요구사항

| ID | 요구사항 |
| --- | --- |
| NFR-1 | THE frontend SHALL 접근 토큰과 재발급 토큰을 브라우저 저장소(localStorage, sessionStorage, IndexedDB)와 JavaScript로 읽을 수 있는 쿠키에 저장하지 않는다. |
| NFR-2 | THE frontend SHALL 인증 화면과 앱 기본 레이아웃의 모든 입력과 버튼을 키보드만으로 조작할 수 있게 한다. |
| NFR-3 | THE frontend SHALL 오류 응답의 `code`마다 정한 한국어 문구를 표시하고, 정하지 않은 `code`에는 공통 문구를 표시한다. |
| NFR-4 | THE frontend SHALL 가로 360px 이상의 모든 화면 너비에서 가로 스크롤 없이 인증 화면과 앱 기본 레이아웃을 표시한다. |
| NFR-5 | WHILE 화면 너비가 1024px 미만이면, THE frontend SHALL 사이드바를 숨기고 메뉴 버튼으로 열고 닫게 한다. |

## 7. 성공 지표

- 로컬 compose와 frontend 개발 서버로 가입 → 로그인 → 새로고침 → 내 정보 확인 → 로그아웃을 시연할 수 있다.
- 접근 토큰 만료(15분) 뒤에도 사용자가 다시 로그인하지 않고 화면을 계속 쓴다.
- 휴대폰(360px)과 데스크톱에서 같은 흐름을 시연할 수 있다.
